# Contributing to Tugra

Thanks for taking the time to contribute. Tugra is early, so the most valuable
contributions right now are bug reports, well-described feature ideas, and
focused pull requests.

## Reporting bugs

Open an issue using the **Bug report** template. Include your environment, steps
to reproduce, what you expected, and what actually happened. Logs help a lot.

## Suggesting features

Open an issue using the **Feature request** template. Explain the problem you're
trying to solve, not just the solution you have in mind.

## Pull requests

1. Open an issue first for anything non-trivial, so we can agree on the approach
   before you spend time on it.
2. Keep PRs small and focused — one concern per PR.
3. Match the existing code style. Add tests where it makes sense.
4. Make sure the project builds and lints before pushing.

## Contributor License Agreement (CLA)

Tugra is dual-licensed (AGPLv3 + commercial). For that to work, every
contributor must agree to the [CLA](CLA.md). The first time you open a pull
request, a bot will ask you to sign it — this is a one-time step.

In short: you keep the copyright to your contribution, and you grant the project
owner the right to license it (including commercially) as part of Tugra.
